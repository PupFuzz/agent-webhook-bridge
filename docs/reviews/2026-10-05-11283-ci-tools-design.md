# Design note — card#11283: CI tools served without `board_tools`, default-on, in the client pack

**Status:** DRAFT r2, revised after design review r1. No code yet. **Card:** bridge board 8 #11283. **Base:** `dev` @ bfd41204.
**Related:** DL-217/222/225, DL-229, DL-360, DL-430/434/445 (pack + update door), DL-451, DL-452, card#11282.

## 0. What the code says today (it changes the card's premise)

- **Every door keys identity on an ENABLED `board_tools` block.** HTTP: `BoardToolAgentResolver::__construct`
  indexes only enabled `http` blocks. ssh: `ToolsCallCommand::handle` refuses a non-"live ssh board-tools agent"
  before its `op` branch. The update door shares both (`AgentToolsController::authenticate` serves `call` and `client`).
- **⇒ An agent with no enabled `board_tools` cannot reach the update door, so it is not on the self-updating client.**
  Measured: prod 0.96.0 `bridge:client-fleet` says "no agent has an enabled board_tools block".
- **The CI tools touch no board.** `CiAwaitTool::call` / `CiAwaitCancelTool::call` use neither `$cfg` nor `$client`.
  The agent is `CallingSeat`, sealed in `BoardToolDispatcher::dispatch`. Delivery goes through
  `AuthoredIntentPush::send`, which reads `channel` config only.
- **The dispatcher couples them anyway.** It calls `WritebackClientFactory::make()` before every tool, so an install
  with no writeback token 503s `ci_await`. It also stamps `ConfigSeenLedger::recordEnabled`.
- **Advertisement is env-only.** In `agent-webhook-bridge-channel.mjs`, `shouldAdvertiseTools()` decides the tool
  list, and `TOOLS_ENABLED` feeds both `INSTRUCTIONS` and the `capabilities` given to `new Server(`, all at module
  load.
- **The pack already carries `bridge-board-call` and the CI definitions.** Reaching the door is the gap.

## 1. Ruling r1 — a CI-only agent reaches the door over ssh only (coordinator ruling, recorded)

An agent with no enabled `board_tools` gets the door **only over ssh, with a pinned key**; that pin is the "requires
setup" half of default-on. Board-tools agents keep exactly today's transport behaviour. Channel-token reuse on HTTP
was dropped because: **(a)** `BoardToolAgentResolver`'s second pass disables EVERY sharer of a bearer value, so a
CI-only agent sharing a channel token with a board-tools agent (several identities per channel are normal; this host
runs three on one socket) would remove that agent's board tools on upgrade; **(b)** the token is not seat-private:
`ChannelPushHandler::handle` sends it as `Authorization: Bearer` to whatever listens on `channel.url`; **(c)** it
would give one agent two transports.

## 2. Config shape — recommend: a door block for CI-only agents, and `ci_tools` as the opt-out

- **`ToolsDoorConfig`** is the door identity every entry point resolves through. The entry points are the files
  matching `grep -rlnE '(BoardToolDispatcher|ClientUpdateDoor) \$' app/Http app/Console` (re-derive at build).
  Enabled `board_tools` ⇒ built from its keys, a **permanent** spelling (no deprecation warning, no edit). Otherwise
  ⇒ from a new ssh-only `tools_door:` block (`enabled`, `ssh_account`, `fleet_view`, `client_update.approval_required`).
- **`ServedTools::for(AgentConfig)` states the door predicate ONCE.** For an agent without an enabled `board_tools`,
  the door is open iff ALL of:
  (1) it has a `channel` block (SF1: `writeback-agent`, `dev-agent` have none ⇒ no door, no "unreachable" warning, no
  fleet entry); (2) `board_tools` is not RETIRED (DL-360) and not SUPPRESSED (malformed never opens a door); (3)
  `tools_door` is not off or suppressed.
- **Never reachable by bearer.** Such an agent is never indexed by `BoardToolAgentResolver`, whose predicate stays
  "enabled `http` `board_tools`". An agent configured as ssh is therefore never reachable by bearer.
- **Plainly disabled `board_tools` does not close the door.** `board_tools: {enabled: false}` (e.g. `prod-agent`'s
  2026-09-13 decline of board tools) leaves the door to the predicate above.
- **Served set:** board tools iff `board_tools` is enabled; CI tools iff the door is open and
  `ci_tools: {enabled: false}` is absent.
  The dispatcher refuses any other name `not_served` before tool resolution, the writeback client and the
  `ConfigSeenLedger` stamp. CI tools implement `SeatTool::call(args, agent)`: no `BoardToolsConfig`, no `KanbanClient`.
- **Classification (SF5): `tools_door` and `ci_tools` reuse `BoardToolsConfig`'s four classes.**
  Absent ⇒ default. `enabled: true` (strict bool) is explicit: a malformed sibling, or `transport`/`auth` in
  `tools_door`, THROWS at load. `enabled: false` ⇒ off. Anything else is default-class and never throws; a malformed
  opt-out value means OFF, with a `bridge:check` FAIL naming it. A `tools_door` beside an enabled `board_tools` throws
  when explicit, and is otherwise suppressed with a FAIL.

## 3. Authentication and trust boundary

- **Credential:** the pinned ssh key; `--agent` is set by the host (`ToolsCallCommand`). The ssh door's check widens
  from "live ssh board-tools agent" to "`ServedTools` door open". No bearer, and no new secret type.
- **Smallest addition:** none beyond the pin. `--role a` gains `--from` and writes `from="127.0.0.1,::1"` on same-box
  pins (SF7). `AuthorizedKeysLine` already parses `from=`; `SshPinnedLineCheck` must accept it.
  ⛔ The `authorized_keys` write is an operator, ask-first step.
- **Boundary.**
  - A CI-only agent gets its own awaits and events, the update door (`client_fleet` behind `fleet_view`) and
    `served_tools`; no board read or write, by construction (§2).
  - ⚠ **Residual (Q2 ruling: stays install-wide).** `ci_await` accepts any repo the install receives
    (`CiAwaitService::receivedRepo`), and `ci_settled` carries that repo's run names, conclusions and URLs. The DL
    records it.
  - On a same-user box the account already reads the bridge's secrets, so the door is not the only boundary.
- **Per-seat read bound (SF3).** The existing `read_cooldown` (`CiAwaitService::evaluateRegistration`) keys on
  stored rows, so cancel-then-register, or fresh SHAs, read GitHub on every call.
  - New `BRIDGE_CI_AWAIT_SEAT_READS_PER_HOUR` (default and range set in the DL) counts registration-triggered reads
    per seat on the cache store (`CACHE_STORE`; default `file`).
  - Over it, a registration is refused `seat_read_limited` with `retry_after`, nothing stored; a cache fault is
    `install_fault.*`, never unbounded. Sweep and delivery reads are per head and outside it. Bound and reason in the DL.

## 4. Advertisement and distribution

- **`served_tools` comes from the bridge, never from a static list** (DL-229: the seat cannot read bridge config).
  Carried on the existing `client_manifest` answer (NIT; the updater fetches it every new launch, so a client-root
  seat pays no second round-trip), and as a standalone `op: served_tools` for servers not started by `entry.mjs`
  and for certification.
- **Cache (MF3).** `client-update.mjs` (not the frozen `entry.mjs`) writes `<root>/served-tools.json`
  (`{launch_id, served, at}`) under its lock. The new root file is named in the DL.
- **Start-up order (MF4).** The channel server resolves the served set BEFORE building `INSTRUCTIONS`, `capabilities`
  and `new Server(`, which today run at module load around L915–L947:
  1. this launch's cache (`AWB_LAUNCH_ID` matches);
  2. else one `served_tools` call, bounded by the `MANIFEST_LEG_MS` shape;
  3. on a timeout or transport error, the last good cache;
  4. with no cache, today's env rule;
  5. an older bridge's well-formed unknown-op 4xx gives the env rule.

  `TOOLS_ENABLED`, the tools capability, the tool list and the instructions' tool sentence are all derived from that
  one set. The bridge's `not_served` refusal is the enforcement point, so every fallback costs no security; it costs
  only an advertised tool that refuses.
- **Residual:** a mid-session config edit refuses a tool advertised at start, with a "restart" reason.
  `tools/list_changed` support in Claude Code is not verified.
- **Seat env (SF8), the cross-repo contract named in the framework FR:**
  `BRIDGE_TOOLS_SSH_TARGET` (required), `BRIDGE_TOOLS_SSH_KEY`/`_PORT` (optional); NO `BRIDGE_TOOLS_ENDPOINT`/
  `_TOKEN`/`_TOKEN_FILE` (both transports set ⇒ the server exits 2; `HTTP_SIBLING_TOOLS_KEYS` in
  `provision-board-tools.py`); `.mcp.json` args pointing at `<root>/entry.mjs` for auto-update.
- **Delivery:**
  a client-root seat whose door now resolves updates at its next launch; an impl seat with no board tools is on no root
  today (§0) and needs one `--role b --bootstrap-client` after the pin (Q3 → framework FR); `--self-cert`/
  `--certify-only` certify with `served_tools`, not `board_my_cards`; an older client advertises board tools that
  refuse `not_served` (DL-445's client-half line warns); a standalone copy updates only once bootstrapped.

## 5. `bridge:check`

- **New per-agent leg `ci_tools.agent`, over the agents `ServedTools` puts in the population (§2 (1)):**
  served, naming the pin (`SshPinnedLineCheck`) · opted out (silence plus the reason) · open but no pin seen (warn
  with the `--role a` command) · classification FAIL (§2).
- **`workflow_run`:** `GitHubWebhookSubscriptionCheck` reads the matched hook's `events` from the list it already
  fetches (no new call) and warns when `workflow_run` is missing while any agent is CI-served; `CiAwaitsCheck`'s
  stored-delivery warn stays as the fallback. (`events` in that list: recall, verify at build.)
- **Fleet:** `ClientFleet` and `ClientFleetCheck` move from "enabled `board_tools`" to "`ServedTools` door open".

## 6. Upgrade and migration

- **Board-tools installs:** no change. **CI-only agents:** the open door is reachable by nobody until the operator
  pins a key, so nothing new is accepted without that act (**Q1 moot**). UPGRADING names the predicate, the opt-outs
  and the §4 seat env.
- **This host — seat `kanban`, agent `prod-agent`:** a channel block, `board_tools: enabled: false`, UDS with no
  token, no github subscription (`receivedRepo` takes the repos from `kanban-solo-ci`/`writeback-agent`).
  `~/.mcp.json` runs the server repo-direct from the prod checkout (no client root ⇒ the §4 env-rule fallback, so
  `board_*` are also listed and refuse until the seat moves to a root). A stray `install-log.jsonl` under
  `~/.local/share/agent-webhook-bridge/client/kanbanboard-agent/` with no `versions/` is unexplained.
  **Steps:** deploy → (ask-first) `--role a` as `kanban` pins `--agent=prod-agent` with `from="127.0.0.1,::1"`
  (allowed: "a non-root account may only pin into ITS OWN authorized_keys"; sshd on :22; no `authorized_keys` yet) →
  seat env `BRIDGE_TOOLS_SSH_TARGET=kanban@localhost` plus the key → restart → `bridge:check` served, `ci_*` listed.

## 7. Test plan (each seen to fail first; the deliberate break is in brackets)

- **T1.** A CI-only agent calls every board tool name → `not_served`, with `Http::preventStrayRequests()`, no
  `WritebackClientFactory` call, no `BoardToolsConfig`. [add board tools to the served set] **T2.** `ci_await` works
  with no writeback token. [today: a natural 503] **T3.** No argument names another seat; cancel touches only own
  rows. [accept a `seat` key]
- **T4.** Door predicate matrix (MF2/SF1): retired, suppressed, no channel, or `tools_door` off ⇒ closed on the ssh
  door, the update door and `served_tools`. A CI-only agent is never resolved by ANY bearer, its channel token
  included. [drop each term in turn]
- **T5.** Property over board × ci × door terms: `served_tools` equals the set the dispatcher serves. [hard-code one
  side]
- **T6.** Classification: an explicit malformed block throws; a default-class one never throws; a malformed opt-out ⇒
  OFF plus FAIL. [treat a malformed value as ON]
- **T7.** Board-tools agents' doors are byte-identical to today, collision disable included. [reorder the resolver
  predicate] **T8.** A CI-only call stamps no `ConfigSeenLedger` row. [stamp it]
- **T9 (node).** Served set → `tools/list`, `capabilities.tools` AND the `INSTRUCTIONS` text. Fallback order: fresh
  cache, call, last cache, env rule, old-bridge 4xx. [static list; instructions from `TOOL_DEFINITIONS`]
- **T10.** The seat read bound refuses `seat_read_limited` past N, across cancel/re-register too. [no bound]
  **T11.** The update door serves a CI-only agent; `client_fleet` 403 without `fleet_view`; approval honoured; `from=`
  pins pass `SshPinnedLineCheck`. **T12.** No new GitHub request from `served_tools`, the doors or the check legs.
