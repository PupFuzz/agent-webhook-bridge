# Design note — card#11283: CI tools served without `board_tools`, default-on, in the client pack

**Status:** DRAFT r3, revised after design reviews r1 and r2. No code yet. **Card:** bridge board 8 #11283.
**Base:** `dev` @ bfd41204. **Related:** DL-217/222/225, DL-229, DL-360, DL-430/434/445, DL-451, DL-452, card#11282.
"UPGRADING" below means the CHANGELOG's § Upgrade warnings for the slice's release.

## 0. What the code says today (it changes the card's premise)

- **Every door keys identity on an ENABLED `board_tools` block.** HTTP: `BoardToolAgentResolver::__construct` indexes
  only enabled `http` blocks. ssh: `ToolsCallCommand::handle` refuses `! $bt->enabled || $bt->transport !== 'ssh'`
  before its `op` branch. The update door shares both (`AgentToolsController::authenticate`). ⇒ An agent with no
  enabled `board_tools` is not on the self-updating client. Measured: prod 0.96.0 `bridge:client-fleet` reports "no
  agent has an enabled board_tools block".
- **The CI tools touch no board.** `CiAwaitTool::call` / `CiAwaitCancelTool::call` use neither `$cfg` nor `$client`.
  The agent is `CallingSeat`; delivery is `AuthoredIntentPush::send` (channel config only). The dispatcher still builds
  `WritebackClientFactory::make()` first (503 without a writeback token) and stamps `ConfigSeenLedger::recordEnabled`.
- **Advertisement is env-only.** `shouldAdvertiseTools()` → `TOOLS_ENABLED` feeds `INSTRUCTIONS` (~L915) and
  `new Server(` (~L943) at module load in `agent-webhook-bridge-channel.mjs`. The pack already carries
  `bridge-board-call` and the CI definitions; reaching the door is the gap.

## 1. Ruling r1 — a CI-only agent reaches the door over ssh only (coordinator ruling, recorded)

An agent with no enabled `board_tools` gets the door **only over ssh, with a pinned key**; the pin is the "requires
setup" half of default-on. Board-tools agents keep today's transport behaviour exactly. HTTP channel-token reuse was
dropped because:
- **(a)** `BoardToolAgentResolver`'s second pass disables EVERY agent sharing a bearer value, so a shared channel token
  would strip a board-tools agent's tools on upgrade;
- **(b)** `ChannelPushHandler::handle` sends the token as a Bearer to whatever listens on `channel.url`, so it is not
  seat-private;
- **(c)** it would give one agent two transports.

## 2. Config shape and the door predicate (stated ONCE, in `ServedTools`)

- **`ToolsDoorConfig` is the door identity of every entry point** (the files from
  `grep -rlnE '(BoardToolDispatcher|ClientUpdateDoor) \$' app/Http app/Console`). With enabled `board_tools` it is
  built from those keys, a **permanent** spelling with no deprecation warning. Otherwise it is built from a new
  ssh-only `tools_door:` block (`enabled`, `ssh_account`, `fleet_view`, `client_update.approval_required`).
- **Door open (`ServedTools::doorOpen`).** With enabled `board_tools`: as today. Without, all three hold:
  (1) `channel.socket` or `channel.url` is set (N6: `AgentConfig` always builds a `ChannelConfig`);
  (2) `board_tools` is neither RETIRED (DL-360) nor SUPPRESSED;
  (3) `tools_door` is neither off nor suppressed.
  `writeback-agent` and `dev-agent` fail (1), so they get no door, no warning and no fleet entry.
- **Door transport (`ToolsDoorConfig::transport`).** `board_tools.transport` when enabled, otherwise always `ssh`.
  - **ssh door serves iff door open AND transport `ssh`** (M1): an http board-tools agent stays refused over ssh, as
    today.
  - **The bearer index serves iff door open AND transport `http`** (today's predicate), so a CI-only agent is never
    reachable by bearer.
- **Served set.** Board tools iff `board_tools` is enabled; CI tools iff the door is open and there is no
  `ci_tools: {enabled: false}`. The dispatcher refuses other names `not_served` before tool resolution, the writeback
  client and the `ConfigSeenLedger` stamp. CI tools implement `SeatTool::call(args, agent)`: no `BoardToolsConfig`,
  no `KanbanClient`.
- **Classification (r1 SF5)** for `tools_door`/`ci_tools`, `BoardToolsConfig`'s four classes:
  - `enabled: true` is explicit: a malformed sibling, or `transport`/`auth` in `tools_door`, throws at load.
  - `enabled: false` turns it off; any other value is default-class and never throws.
  - A malformed opt-out means OFF, plus a `bridge:check` FAIL.
  - A `tools_door` beside enabled `board_tools` throws if explicit, else is suppressed with a FAIL.
- **Door refusals gain a `reason` (S1).** Today ssh exits 2 before the `op` branch, and exit 2 also means config error,
  unknown agent or 5xx. A closed door answers `{ok:false, reason: "door_closed"}` on both transports (additive, like
  DL-449's codes). The new bridge never answers `served_tools` with 422.

## 3. Authentication, trust boundary, read bound

- **Credential:** the pinned ssh key; `--agent` is host-set. No bearer, no new secret type. `--role a` gains `--from`
  and writes `from="127.0.0.1,::1"` on same-box pins (`AuthorizedKeysLine` already parses `from=`:
  `test_quoted_comma_in_from_does_not_split_the_option_list`). ⛔ The `authorized_keys` write is an operator,
  ask-first step.
- **Pin certification (M2).** Today `CheckCommand` builds the `BoardToolsSsh` population from `boardToolsEnabled`
  filtered to ssh, inside the enabled-`board_tools` branch, and `SshPinnedLineCheck` takes `boardTools->sshAccount`.
  A CI-only pin (e.g. one missing `no-port-forwarding`) is therefore never certified.
  - Re-key `BoardToolsSsh` and the DL-225 advisory's exclusion onto `ServedTools`' ssh-door population, outside that
    guard, with the account from `ToolsDoorConfig`.
  - `--probe-tools-ssh` (`SshTransportProbe::probeLive`, which sends `board_my_cards`) uses `served_tools` for CI-only
    agents (S5).
- **Boundary.** A CI-only agent gets its own awaits and events, the update door (`client_fleet` behind `fleet_view`)
  and `served_tools`; no board read or write, by construction.
  - ⚠ **Residual (Q2: install-wide).** `ci_await` accepts any repo the install receives
    (`CiAwaitService::receivedRepo`), and `ci_settled` carries that repo's run names, conclusions and URLs. Recorded in
    the DL.
  - On a same-user box the account already reads the bridge's secrets.
- **Per-seat read bound (r1 SF3, reshaped by M3).** The cooldown in `evaluateRegistration` keys on stored rows, so
  cancel-then-register, or fresh SHAs, read GitHub on every call.
  - New `BRIDGE_CI_AWAIT_SEAT_READS_PER_HOUR` counts registration reads per seat with `RateLimiter::hit($key, 3600)`
    (S3: not `Cache::increment`, whose `FileStore` path stores a missing key with TTL 0 and no lock).
  - Over the bound, **the await is STORED and the read skipped**, answering `waiting` with
    `read_skipped: 'seat_read_limited'` and `retry_not_before` (existing fields, beside `cooldown`/`rate_limited`).
    A limiter fault also only skips the read.
  - The sweep or a `workflow_run` delivery settles it, and `seatLoad`'s `maxPerSeat` caps the awaits held.
  - No new refusal. Bound and reason go in the DL.

## 4. Advertisement and distribution

- **`served_tools` comes from the bridge** (DL-229: the seat cannot read bridge config). It rides on the existing
  `client_manifest` answer (fetched every new launch), and is also a standalone `op: served_tools` for servers not
  started by `entry.mjs` (repo-direct included) and for certification.
- **Cache (r1 MF3, N5).** `client-update.mjs` writes `<root>/served-tools.json` (`{launch_id, served, at}`) under its
  lock, only when a manifest answer carries `served_tools`. It is an **add-only cross-release contract**, named in the
  DL. The first launch after S2's pack runs the OLD updater, so no cache that launch; a failed manifest leaves step 2.
- **Start-up, before `INSTRUCTIONS` / `capabilities` / `new Server(` (r1 MF4):**
  1. this launch's cache (`AWB_LAUNCH_ID` matches);
  2. one `served_tools` call (`MANIFEST_LEG_MS` shape);
  3. `reason: door_closed` → no bridge tool;
  4. a timeout, transport error or reason-less exit 2 / 5xx → the last good cache, else today's env rule;
  5. an old bridge (exit 1 or 422, no `reason`, error prefix `unknown client-update`) → today's env rule.
- **Advertised = served ∩ `TOOL_DEFINITIONS`.** `ADVERTISE_ANY_TOOL = TOOLS_ENABLED || CLEAR_CONTEXT_ENABLED` is kept,
  so `clear_context` survives an empty set (N2). `not_served` is the enforcement point, so a fallback costs only an
  advertised tool that refuses; cache tampering is not a finding.
- **Residual:** a mid-session config edit makes a start-time tool refuse with "restart"; `tools/list_changed` in
  Claude Code is unverified.
- **Seat env (r1 SF8)** — the cross-repo contract, also in UPGRADING and the framework FR:
  - `BRIDGE_TOOLS_SSH_TARGET` required; `BRIDGE_TOOLS_SSH_KEY` and `_PORT` optional;
  - NO `BRIDGE_TOOLS_ENDPOINT`/`_TOKEN`/`_TOKEN_FILE` (both transports ⇒ the server exits 2; `HTTP_SIBLING_TOOLS_KEYS`);
  - `.mcp.json` args pointing at `<root>/entry.mjs` for auto-update.
- **Delivery.**
  - A client-root seat whose door resolves updates at its next launch.
  - An impl seat with no board tools is on no root today (§0) and needs one `--role b --bootstrap-client` after the
    pin (Q3 → framework FR).
  - `--self-cert` / `--certify-only` certify with `served_tools`.
  - Older clients advertise board tools that refuse (DL-445's client-half line warns); a standalone copy updates once
    bootstrapped.

## 5. `bridge:check`

- **New leg `ci_tools.agent`, over agents with an open door:**
  - served: names the pin (certified by the re-keyed `BoardToolsSsh`) and the last successful call;
  - opted out: silence plus the reason;
  - open with no pin seen: warn with the `--role a` command;
  - classification: FAIL.
- **N3 ruling:** `ClientHalfLedger::record` keeps stamping SeatTool calls (one ledger), and `ci_tools.agent` reads it.
- **`workflow_run` (S2).** `hasRepoWebhookFor` returns on the first match, and `GitHubHookListAnswer` has no `events` or
  `active`.
  - Collect every matching hook, skip inactive ones, and accept `"*"` or a literal `workflow_run`.
  - Widen the answer type; same pages, no new call.
  - Warn when nothing satisfies while any agent is CI-served; `CiAwaitsCheck`'s stored-delivery warn stays as the
    fallback.
- **Fleet:** `ClientFleet` and `ClientFleetCheck` move from "enabled `board_tools`" to "`ServedTools` door open".

## 6. Upgrade and migration

- **Board-tools installs:** no change.
- **CI-only agents:** reachable by nobody until a pin (Q1 moot). UPGRADING says:
  - every agent whose channel sets `socket`/`url` gets an open door, and a no-pin warn until pinned;
  - **pick ONE identity per seat** (the one whose `coord_seat` names it, or whose channel the seat's `.mcp.json`
    binds), and give the others sharing that channel `tools_door: {enabled: false}`;
  - the §4 seat env.
- **This host — seat `kanban`, agent `prod-agent`.**
  - Config: channel socket set, `board_tools: enabled: false`, UDS with no token, no github subscription
    (`receivedRepo` takes the repos from `kanban-solo-ci`/`writeback-agent`).
  - **`kanban-solo` and `kanban-solo-ci` share that socket (S6): both get `tools_door: {enabled: false}`.**
  - The server runs repo-direct from the prod checkout. After deploy it calls standalone `served_tools` (§4 step 2), so
    once pinned it lists only `ci_*` (N4); the env rule is only the bridge-unreachable fallback.
  - A stray `install-log.jsonl` under `~/.local/share/agent-webhook-bridge/client/kanbanboard-agent/` (no `versions/`)
    is unexplained.
  - **Steps:**
    1. deploy;
    2. (ask-first) `--role a` as `kanban` pins `--agent=prod-agent` with `from="127.0.0.1,::1"` (a non-root account
       may pin into its own `authorized_keys`; sshd on :22; none exists yet);
    3. add the two solo `tools_door` opt-outs;
    4. set the seat env `BRIDGE_TOOLS_SSH_TARGET=kanban@localhost` plus the key;
    5. restart;
    6. `bridge:check` shows served and certified, and `tools/list` shows `ci_*` only.

## 7. Test plan (each seen to fail first; the deliberate break is in brackets)

- **T1.** A CI-only agent calls each board tool → `not_served`, with `Http::preventStrayRequests()`, no
  `WritebackClientFactory`, no `BoardToolsConfig`. [remove the ServedTools gate]
- **T2.** `ci_await` works with no writeback token. [today: 503]
- **T3.** No argument names another seat; cancel touches only own rows. [accept a `seat` key]
- **T4.** Retired, suppressed, no `socket`/`url`, or `tools_door` off ⇒ `door_closed` on the ssh door, update door and
  `served_tools`. **An http board-tools agent is refused over ssh.** A CI-only agent resolves by no bearer. [drop each
  term; drop the transport term]
- **T5.** Property over board × ci × door × transport: `served_tools` equals the dispatcher's served set. [hard-code
  one side]
- **T6.** Explicit malformed throws; default-class never throws; malformed opt-out ⇒ OFF + FAIL. [read malformed as ON]
- **T7.** Board-tools doors are byte-identical to today, collision disable and http-over-ssh refusal included. [reorder
  predicates]
- **T8.** A CI-only call stamps `ClientHalfLedger` but not `ConfigSeenLedger`. [swap them]
- **T9 (node).** Served set → `tools/list`, `capabilities.tools` and the `INSTRUCTIONS` text; `clear_context` survives
  an empty set; the fallback order, including `door_closed` → none and the exact old-bridge test. [static list]
- **T10.** Past N reads: stored, `waiting`/`seat_read_limited`/`retry_not_before`, no GitHub request, across
  cancel/re-register; a limiter fault behaves the same. [read anyway]
- **T11.** A CI-only pin missing `no-port-forwarding` → `BoardToolsSsh` FAIL; `from=` pins certify. [drop a CI-only
  agent from the slot population]
- **T12.** Hook `events` fixtures (`"*"`, two matching hooks, inactive); no new GitHub request from `served_tools`, the
  doors or the check legs. [first-match return]
