# Design note — card#11283: CI tools for agents with no board scope, in the client pack

**Status:** DRAFT r4. The design changed after review r3. No code yet. **Card:** bridge board 8 #11283.
**Base:** `dev` @ bfd41204. **Related:** DL-217/225/229/360/430/445/451/452, card#11282, framework card#11285.
"UPGRADING" means the CHANGELOG's § Upgrade warnings.

## 0. Premise

- **Every door keys identity on an enabled `board_tools` block** (`BoardToolAgentResolver::__construct`,
  `ToolsCallCommand::handle`). So does the update door (`AgentToolsController::authenticate`). Measured on prod 0.96.0:
  `bridge:client-fleet` reports "no agent has an enabled board_tools block".
- **Today an enabled block needs a board scope.** `BoardToolsConfig` calls `requireInt` on `board_id`, `swimlane_id`
  and `create_stage_id`.
- **The CI tools touch no board.** `CiAwaitTool::call` / `CiAwaitCancelTool::call` use neither `$cfg` nor `$client`.

## 1. Why the `tools_door` split was abandoned (r1–r3)

r1–r3 split a `tools_door` identity out of `board_tools`. Each round's MUST-FIXes (4 → 3 → 3) landed in the same place:
the definition of the door population. Every fix moved that definition, and every move left another copy of the old
`boardTools->enabled` predicate, which is spread across about 13 files (ClientFleet, ClientApproveCommand, NextSteps,
ProvisionToolsCommand, SshLiveProbeCheck, the CheckCommand guard and others). That is #15's non-convergence signal. So
the population no longer moves: a CI-only agent IS an enabled `board_tools` agent whose board scope is absent. Every
existing door, slot, ledger, fleet and provisioning predicate applies to it unchanged. The r1 ssh-only ruling, the
door-predicate and transport work, and the reasons for dropping channel-token reuse are moot. Board-tools transports
are unchanged, and a scope-less http agent behaves like any http agent today.

## 2. Shape

- **Parse (`BoardToolsConfig`).** An EXPLICIT `enabled: true` block with `board_id`, `swimlane_id` and
  `create_stage_id` ALL absent is valid and **scope-less**.
  - `shared_swimlane_id`, `coord_board_id` or `address_tags` without a scope count as a partial scope.
  - A partial scope takes today's path: explicit throws, default-class suppresses with a FAIL.
  - A DEFAULT-class block (`enabled` absent) with no scope keeps today's suppress. Upgrading therefore opens no door on
    any existing YAML. Every block that is scope-less and valid after the change THREW before it.
- **`ServedTools::for($agent)`** is the one function deciding what is served.
  - Scoped: `board_*` plus `ci_*`. Scope-less: `ci_*` only. Disabled, suppressed or retired: nothing.
  - `ci_tools: {enabled: false}` removes `ci_*`, and a malformed value means OFF plus a FAIL.
- **The dispatcher gate.** `BoardToolDispatcher::dispatch` refuses an unserved name with `not_served` BEFORE
  `WritebackClientFactory::make()`, before any tool resolves and before any kanban client exists.
  - This gate is load-bearing: the board tools cast `(int) $cfg->boardId`, so a null scope would read board 0.
  - CI tools also skip the writeback client, because they never use it.
- **`served_tools`.** It is carried on the `client_manifest` answer and as a standalone op, answering
  `{ok, agent, served:[…]}`. `agent` is an identity echo. The answer comes from the same function.

## 3. Trust boundary, read bound

- **Credentials** are whatever the agent's transport uses today. A same-box ssh pin carries `from="127.0.0.1,::1"`,
  written by the operator as an ask-first step (`AuthorizedKeysLine` already parses `from=`).
- **No board access, by construction.** A scope-less agent is never handed a board tool.
- **Q2 residual, ruled install-wide.** `ci_await` accepts any repo the install receives (`CiAwaitService::receivedRepo`),
  and `ci_settled` carries that repo's run names, conclusions and URLs. This goes in the DL.
- **Per-seat read bound.** The cooldown in `evaluateRegistration` keys on stored rows, so cancel-then-register, or fresh
  SHAs, read GitHub on every call.
  - New `BRIDGE_CI_AWAIT_SEAT_READS_PER_HOUR`, counted by `RateLimiter::hit($agentKey, 3600)`.
  - Over the bound, the await is STORED and the read skipped. The answer is `waiting` with
    `read_skipped: 'seat_read_limited'` and a `retry_not_before` instant.
  - That instant goes in the ANSWER only, never in the `retry_not_before` COLUMN, which blocks every read of the head
    (delivery and sweep included).
  - A limiter fault also only skips the read. No new refusal.
  - The widened `read_skipped` enumeration is declared in `board-tools.md` and in the `ci_await` tool description.

## 4. The denominator: every site that reads a scope field from a `BoardToolsConfig`

**Derivation.** `grep -rnE -- '->(boardId|swimlaneId|createStageId|sharedSwimlaneId|coordBoardId|addressTags)\b' app`,
kept to files that hold a `BoardToolsConfig` (`BoardToolsConfig|boardTools|ResolvedBoardToolAgent`). Writeback
mapping and handler hits read `WritebackMapping`, not this class, and are excluded.

| Site | Scope-less behaviour |
| --- | --- |
| `Board{MyCards,Create,Correct,Take,Comment,GetCards,Search}Tool` (`(int) $cfg->boardId` …) | unreachable: the §2 gate refuses first (T1) |
| `BoardSearchTool` other-agents lane merge (`$tools->boardId === $boardId`) | null never matches, so the agent is excluded; no edit |
| `BoardToolsBoardStateCheck` `$bt->boardId === null` guard | already silent; reword its reason to name scope-less |
| `BoardToolsHttpProbeCheck` scope-header match | edit: probe sends `served_tools` and matches the `agent` echo; falls back to `board_my_cards` on an old bridge |
| `SshLiveProbeCheck` expected `board_id`/`swimlane_id` + `SshTransportProbe::probeLive` | same edit as the HTTP probe |
| `ConfigSeenLedger::recordEnabled` (`board_id`, `swimlane_id`) | the columns are nullable (`board_tools_config_seen` migration); no edit |
| `ProvisionToolsCommand` block template (`board_id: <…>` text) | edit: print the scope-less form as the impl-seat variant |

**Found by reading, outside the grep.** These read `->enabled` meaning "may use board tools", not "has a door":
- `AgentKanbanUserRosterCheck` `$takes = $agent->boardTools?->enabled` (and L114/135/213/215). Without an edit, a
  scope-less agent with no roster kanban user would FAIL for `board_take_card`, which it cannot call. Re-key "takes" on
  `ServedTools`.
- `CheckCommand` board-tools client guard ("enabled for N agent(s) but the kanban writeback client is unavailable").
  Count scoped agents only.
- ⚠ A full audit of the `->enabled` readers for this meaning is S1's first task; this list is not claimed complete.
- **Checked, and no scope read:** `ClientFleet`, `NextSteps`, `BoardToolsClientHalfCheck`, `SeatKanbanUser`.

## 5. Advertisement (S2)

These are r2's decisions, kept unchanged.
- **Start-up order.** The served set resolves BEFORE `INSTRUCTIONS`, `capabilities` and `new Server(` (about L915–L947
  of `agent-webhook-bridge-channel.mjs`). Its sources, in order:
  1. this launch's `<root>/served-tools.json`;
  2. one `served_tools` call;
  3. `reason: not_served` / door refused → no bridge tool;
  4. timeout, transport error, or a reason-less exit 2 / 5xx → the last good cache, else today's env rule;
  5. an old bridge (exit 1 or 422, no `reason`, `unknown client-update` prefix) → today's env rule.
- **The cache** is written by `client-update.mjs` only when the manifest answer carries `served_tools`. It is an
  add-only cross-release contract, named in the DL.
- **What gets advertised.** Advertised = served ∩ `TOOL_DEFINITIONS`, and the INSTRUCTIONS text is derived from it.
  `ADVERTISE_ANY_TOOL = TOOLS_ENABLED || CLEAR_CONTEXT_ENABLED`.
- **Enforcement** stays with `not_served`, so a fallback only advertises a tool that refuses.

## 7. Default-on, the cross-repo contract, Q4

- **The bridge's default for an agent with NO block is unchanged** (the NextSteps `no_block` line).
- **Automatic setup is the framework's job** (card#11285). Its onboarding writes a scope-less
  `board_tools: {enabled: true}` block plus the ssh pin and the seat env (`BRIDGE_TOOLS_SSH_TARGET`, `_KEY`, `_PORT`).
- **DECLARED** in `board-tools.md` and the framework FR: "a scope-less enabled block serves `ci_*` only". It is
  CHECKED by T1/T5 on the bridge side. card#11282's runbook names the scope-less form as the impl-seat setup.
- **Q4 (revised).** Impl seats DO get a `board_tools` block. It is scope-less and grants no board access. The operator's
  rule "impl agents use kbcard, no board tools" holds, because no board tool is served.
- **Q1, Q3** are moot or with the framework. **Q2** is ruled in §3.

## 8. This host

- `prod-agent.yml` gets `board_tools: {enabled: true, ssh_account: kanban}` with no scope. The other agents stay
  `enabled: false`.
- **Steps:**
  1. deploy;
  2. (ask-first) `--role a` as `kanban` pins `--agent=prod-agent` with `from="127.0.0.1,::1"`;
  3. seat env `BRIDGE_TOOLS_SSH_TARGET=kanban@localhost` plus the key;
  4. restart;
  5. `bridge:check`, where the existing ssh slots certify the pin.
- The repo-direct server calls `served_tools` and lists `ci_*` only.

## 9. Tests (each seen to fail first; the deliberate break is in brackets)

- **T1.** A scope-less agent calls each `board_*` tool → `not_served`, with `Http::preventStrayRequests()` and no
  `WritebackClientFactory` call. [remove the gate]
- **T2.** `ci_await` works with no writeback token. [today: 503]
- **T3.** Parse matrix:
  - scope-less explicit → valid;
  - partial scope → throw (explicit) / suppress (default-class);
  - default-class with no scope → suppressed;
  - malformed `ci_tools` → OFF + FAIL.
  [accept partial]
- **T4.** Scoped agents: dispatch and every check are byte-identical to today. [serve `ci_*` only to scoped]
- **T5.** `served_tools` equals the dispatcher's served set over scope × `ci_tools` × enabled state. [hard-code one]
- **T6.** The roster leg does not FAIL a scope-less agent with no roster user, and the client guard ignores it. [revert
  the re-key]
- **T7.** The probes certify a scope-less agent via the `agent` echo and fall back on an old bridge. [match on scope]
- **T8.** The read bound: stored, `seat_read_limited`, no GitHub request, column untouched. [write the column]
- **T9 (node).** The S2 ladder, the INSTRUCTIONS text and `clear_context`. [static list]
- **T10.** Hook fixtures `"*"`, two hooks, inactive. [first-match return]
