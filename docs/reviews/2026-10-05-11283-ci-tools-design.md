# Design note — card#11283: CI tools for agents with no board scope, in the client pack

**Status:** r4 design, S1 BUILT (DL-461; § As built). **Card:** bridge board 8 #11283. **Base:** `dev` @ bfd41204.
**Related:** DL-217/225/229/360/430/445/451/452, card#11282, framework card#11285. "UPGRADING" = CHANGELOG § Upgrade warnings.

## 0. Premise

Every door, the update door included, keys identity on an enabled `board_tools` block (`BoardToolAgentResolver::__construct`,
`ToolsCallCommand::handle`, `AgentToolsController::authenticate`; prod 0.96.0 `bridge:client-fleet`: "no agent has an
enabled board_tools block"). An enabled block needs a scope (`BoardToolsConfig` `requireInt` on `board_id`,
`swimlane_id`, `create_stage_id`). The CI tools touch no board (`CiAwaitTool::call` / `CiAwaitCancelTool::call` use
neither `$cfg` nor `$client`).

## 1. Why the `tools_door` split was abandoned (r1–r3)

r1–r3 split a `tools_door` out of `board_tools`. MUST-FIXes ran 4 → 3 → 3, all in the door-population definition:
each fix moved it and left another copy of the enabled-block predicate (re-derive:
`grep -rnE -- 'boardToolsEnabled|boardTools\??->enabled|\$bt->enabled' app`) — #15's non-convergence signal. Now the population does not move: a CI-only agent IS an enabled `board_tools` agent with no
board scope, so every door, slot, ledger, fleet and provisioning predicate applies unchanged. The r1 ssh-only ruling
and the door/transport work are moot; a scope-less http agent behaves like any http agent today.

## 2. Shape

- **Parse.** An EXPLICIT `enabled: true` block with `board_id`, `swimlane_id`, `create_stage_id` ALL absent is valid
  and **scope-less**. A partial scope (including `shared_swimlane_id`/`coord_board_id`/`address_tags` with no scope)
  takes today's path: explicit throws, default-class suppresses + FAIL. A DEFAULT-class block with no scope keeps
  today's suppress, so upgrading opens no door: every newly valid block THREW before.
- **`ServedTools::namesFor()`** is the one function deciding what is served.
  Scoped: `board_*` + `ci_*`; scope-less: `ci_*`; disabled/suppressed/retired: nothing. `ci_tools: {enabled: false}`
  removes `ci_*` (a malformed value means OFF + FAIL).
- **Gate.** `BoardToolDispatcher::dispatch` refuses an unserved name `not_served` BEFORE `WritebackClientFactory::make()`
  and tool resolution. Load-bearing: board tools cast `(int) $cfg->boardId`, so a null scope would read board 0. CI
  tools skip the writeback client (they never use it).
- **`served_tools`**, from the same function, on the `client_manifest` answer and as a standalone op:
  `{ok, op, agent, served:[…]}`, `agent` being an identity echo.

## 3. Trust boundary, read bound

- **Credentials:** the agent's transport, as today. A same-box ssh pin carries `from="127.0.0.1,::1"`, written by the
  operator (ask-first; `AuthorizedKeysLine` already parses `from=`). No board access, by construction (§2 gate).
- **Q2 residual, ruled install-wide** (in the DL): `ci_await` accepts any repo the install receives
  (`CiAwaitService::receivedRepo`), and `ci_settled` carries that repo's run names, conclusions and URLs.
- **Per-seat read bound.** `evaluateRegistration`'s cooldown keys on stored rows, so cancel/re-register or fresh SHAs
  read GitHub every call. New `BRIDGE_CI_AWAIT_SEAT_READS_PER_HOUR` via `RateLimiter::hit($agentKey, 3600)`. Over it,
  or on a limiter fault, the await is STORED and the read skipped: `waiting`, `read_skipped: 'seat_read_limited'`,
  `retry_not_before` in the ANSWER only, never the COLUMN (which blocks delivery and sweep reads of the head). No new
  refusal. The widened `read_skipped` set is declared in `board-tools.md` and the `ci_await` description.

## 4. The denominator: every site that reads a scope field from a `BoardToolsConfig`

Derivation: `grep -rnE -- '->(boardId|swimlaneId|createStageId|sharedSwimlaneId|coordBoardId|addressTags)\b' app`,
kept to files matching `BoardToolsConfig|boardTools|ResolvedBoardToolAgent` (writeback hits read `WritebackMapping`).

| Site | Scope-less behaviour |
| --- | --- |
| `Board{MyCards,Create,Correct,Take,Comment,GetCards,Search}Tool` (`(int) $cfg->boardId` …) | unreachable: the §2 gate refuses first (T1) |
| `BoardSearchTool` other-agents lane merge (`$tools->boardId === $boardId`) | null never matches, so the agent is excluded; no edit |
| `BoardToolsBoardStateCheck` `$bt->boardId === null` guard | already silent; reword its reason to name scope-less |
| `BoardToolsHttpProbeCheck` scope-header match | edit: probe sends `served_tools` and matches the `agent` echo; falls back to `board_my_cards` on an old bridge |
| `SshLiveProbeCheck` expected `board_id`/`swimlane_id` + `SshTransportProbe::probeLive` | same edit as the HTTP probe; the provisioner's `--self-cert`/`--certify-only` likewise |
| `ConfigSeenLedger::recordEnabled` (`board_id`, `swimlane_id`) | the columns are nullable (`board_tools_config_seen` migration); no edit |
| `ProvisionToolsCommand` block template (`board_id: <…>` text) | edit: print the scope-less form as the impl-seat variant |

**Found by reading** — `->enabled` read as "may use board tools", not "has a door":
- `AgentKanbanUserRosterCheck` `$takes = …->enabled` (also L114/135/213/215): would FAIL a scope-less agent with no
  roster user for `board_take_card`, which it cannot call. Re-key on `ServedTools`.
- `CheckCommand` board-tools client guard ("enabled for N agent(s) but the kanban writeback client is unavailable"):
  count scoped agents only.
- ⚠ Not claimed complete: auditing every `->enabled` reader for this meaning is S1's first task. Checked with no scope
  read: `ClientFleet`, `NextSteps`, `BoardToolsClientHalfCheck`, `SeatKanbanUser`.

## 5. Advertisement (S2); `bridge:check` (S1)

r2's decisions, kept. The served set resolves BEFORE `INSTRUCTIONS`/`capabilities`/`new Server(` (~L915–L947), from:
this launch's `<root>/served-tools.json` → one `served_tools` call → (door refused → no bridge tool) → on timeout,
transport error or reason-less exit 2/5xx the last good cache, else today's env rule → old bridge (exit 1 or 422, no
`reason`, `unknown client-update` prefix) → env rule. `client-update.mjs` writes the cache only when the manifest
carries `served_tools` (add-only cross-release contract, in the DL). Advertised = served ∩ `TOOL_DEFINITIONS`, with
INSTRUCTIONS derived from it; `ADVERTISE_ANY_TOOL = TOOLS_ENABLED || CLEAR_CONTEXT_ENABLED`. `not_served` enforces,
so a fallback only advertises a tool that refuses.

**`bridge:check`:** the §4 edits, and no new per-agent leg. `workflow_run`: `hasRepoWebhookFor` collects every
matching hook, skips inactive ones, accepts `"*"` or `workflow_run`; `GitHubHookListAnswer` widens; no new GitHub call.

## 6. Default-on, the cross-repo contract, Q4, this host

- The bridge default for an agent with NO block is unchanged (NextSteps `no_block`). The automatic part is the
  framework's onboarding (card#11285): it writes scope-less `board_tools: {enabled: true}`, the ssh pin, and the seat
  env (`BRIDGE_TOOLS_SSH_TARGET`, `_KEY`, `_PORT`). **DECLARED** in `board-tools.md` and the framework FR ("a
  scope-less enabled block serves `ci_*` only"), **CHECKED** by T1/T5; card#11282's runbook names it as impl-seat setup.
- **Q4 (revised):** impl seats DO get a `board_tools` block. It is scope-less and grants no board access, so the rule
  "impl agents use kbcard, no board tools" holds: no board tool is served. Q1/Q3 moot or framework; Q2 in §3.
- **This host:** `prod-agent.yml` gets `board_tools: {enabled: true, ssh_account: kanban}`, no scope; the other agents stay
  `enabled: false`. Steps: deploy → (ask-first) `--role a` as `kanban` pins `--agent=prod-agent` with
  `from="127.0.0.1,::1"` → seat env `BRIDGE_TOOLS_SSH_TARGET=kanban@localhost` plus the key → restart → `bridge:check`
  (existing ssh slots certify the pin). The repo-direct server calls `served_tools` and lists `ci_*` only.

## As built (S1, DL-461) — where the build differs from the text above

- `ServedTools` (registry-backed list) applies `ServedToolsRule` (no registry), and the take path asks the rule:
  naming the registry there pulled every tool into `BoardTakeCardRefusalReasonCoverageTest`'s census.
- `not_served` is 422 / ssh exit 1, after `unknown_tool`, before the args check and the writeback client.
- `ci_tools` lives in the `board_tools` block. `fleet_view` / `description_max_bytes` throw on a scope-less block.
- `--self-cert` asks `served_tools` (identity echo), then makes ONE served-tool call (`board_my_cards`, else the
  write-nothing `ci_await_cancel`), so the client-half row is still stamped. It falls back to `board_my_cards` only on
  a bridge that does not know the op. There is no bridge-side old-bridge fallback.
- The hook walk reads past the first match (`HookDeliverySettings`); `found` is unchanged.
- The ssh live probe sends `ci_await_cancel` to an all-scope-less target. On a mixed target it sends `board_my_cards`;
  a `not_served` refusal arrives at ssh exit 1 and is read before the exit gate, then followed with `ci_await_cancel`.
- New per-agent check leg `ci_tools.agent` (block shape and served set). §5 named no such leg; the served set needed
  one surface that prints it per agent.
- Not built here: channel-server advertisement from `served_tools` (S2).
